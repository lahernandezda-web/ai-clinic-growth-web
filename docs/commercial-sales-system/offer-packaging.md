# Estructura de ofertas PLEXAI (sin precios cerrados)

**Principio:** cada oferta resuelve un problema acotado, con criterios de éxito medibles y exclusiones explícitas. Los importes se acuerdan en propuesta formal, no en este documento.

---

## 1. Auditoría gratuita de procesos

| Campo | Contenido |
|-------|-----------|
| **Para quién es** | Negocios con solicitudes comerciales recurrentes y dolor verbalizable; score cualificación ≥ 51 |
| **Problema que resuelve** | Falta de claridad sobre dónde se pierde tiempo o leads |
| **Qué incluye** | Reunión 30–60 min, preguntas por áreas, detección de repeticiones, informe con 1–3 automatizaciones priorizadas |
| **Qué no incluye** | Implementación, precio cerrado, revisión legal, datos clínicos, acceso a sistemas internos profundos |
| **Ejemplos** | Clínica dental con leads de fin de semana sin registro; academia con formularios dispersos |
| **Criterios de éxito** | Cliente entiende MVP recomendado; siguiente paso agendado; sin promesas de canales no MVP |
| **Cuándo ofrecerla** | Tras cualificación positiva; antes de propuesta de pago; como puerta de entrada honesta |

---

## 2. MVP de automatización pequeña

| Campo | Contenido |
|-------|-----------|
| **Para quién es** | Cliente post-auditoría con proceso mínimo y responsable interno |
| **Problema** | Un cuello de botella concreto (registro, aviso, clasificación simple) |
| **Incluye** | Diseño flujo, implementación acotada, guía uso, sesión validación, soporte piloto acordado |
| **No incluye** | WhatsApp API, calendario, voz, CRM completo, múltiples integraciones |
| **Ejemplos** | Formulario web → hoja + email al responsable; etiquetado por tipo de servicio |
| **Éxito** | Métrica acordada mejora vs. línea base (cualitativa o numérica sin garantía absoluta) |
| **Cuándo** | Tras informe aceptado; decisor comprometido |

---

## 3. Sistema de seguimiento comercial

| Campo | Contenido |
|-------|-----------|
| **Para quién** | Negocios con leads registrados pero sin cadencia de seguimiento |
| **Problema** | Leads “fríos” por olvido, no por falta de captación |
| **Incluye** | Estados del lead, recordatorios **internos** al equipo, plantillas de seguimiento, reporting básico |
| **No incluye** | Secuencias masivas tipo spam; mensajes automáticos al cliente sin supervisión; CRM enterprise |
| **Ejemplos** | Recordatorio a recepción si sin contacto 48 h; lista semanal de pendientes |
| **Éxito** | Reducción de leads sin seguimiento > X días (medido) |
| **Cuándo** | Tras MVP de registro funcionando; madurez digital ≥ 2 |

---

## 4. Sistema de captación y clasificación de solicitudes

| Campo | Contenido |
|-------|-----------|
| **Para quién** | Muchos canales (web, IG, teléfono) y caos de entrada |
| **Problema** | Solicitudes duplicadas, sin origen, sin prioridad |
| **Incluye** | Punto(s) de entrada acordados, reglas de clasificación, registro unificado, origen/UTM |
| **No incluye** | Chatbot médico; diagnóstico; WhatsApp API salvo fase 2 |
| **Ejemplos** | Clasificar “urgencia / info / presupuesto” según palabras clave + revisión humana |
| **Éxito** | % solicitudes con origen y categoría completos |
| **Cuándo** | Volumen medio-alto; reglas de negocio escritas o dispuestos a escribirlas |

---

## 5. Sistema de reporting básico

| Campo | Contenido |
|-------|-----------|
| **Para quién** | Decisor que no ve números semanales |
| **Problema** | Decisiones a ciegas; datos en varias hojas |
| **Incluye** | Dashboard o informe semanal automático desde fuente acordada (hoja/base) |
| **No incluye** | BI enterprise; predicción mágica; datos clínicos |
| **Ejemplos** | Email lunes: solicitudes semana, tiempo medio hasta aviso, leads pendientes |
| **Éxito** | Decisor usa el informe 4 semanas seguidas |
| **Cuándo** | Fuente de verdad ya existe (post MVP registro) |

---

## 6. Fase 2 — Integraciones y canales

| Campo | Contenido |
|-------|-----------|
| **Para quién** | MVP en producción estable ≥ 30–60 días |
| **Problema** | Necesidad real de conectar CRM, WhatsApp Business API, calendario, etc. |
| **Incluye** | Diagnóstico técnico, alcance por integración, pruebas, documentación |
| **No incluye** | “Todo conectado” sin lista cerrada; integraciones no evaluadas |
| **Ejemplos** | Sincronizar leads con CRM ligero; webhook a herramienta de email marketing |
| **Éxito** | Integración acordada funciona en casos test definidos |
| **Cuándo** | Métricas MVP validadas; presupuesto y responsable técnico cliente |

---

## 7. Mantenimiento / optimización mensual

| Campo | Contenido |
|-------|-----------|
| **Para quién** | Clientes con automatización en producción |
| **Problema** | Rotura por cambios de copy, temporada, personal nuevo |
| **Incluye** | Horas de soporte acordadas, ajustes menores, revisión métricas, propuestas de mejora |
| **No incluye** | Nuevas integraciones grandes (van como proyecto); desarrollo ilimitado |
| **Ejemplos** | Actualizar plantillas temporada; corregir flujo tras cambio de formulario |
| **Éxito** | Uptime operativo del flujo; métricas estables o mejorando |
| **Cuándo** | Tras entrega MVP; cliente valora continuidad |

---

## Cómo combinar ofertas (ruta típica)

```
Auditoría gratuita
    → MVP automatización pequeña
        → Seguimiento comercial O reporting (según dolor)
            → Fase 2 integraciones
                → Mantenimiento mensual
```

No saltar a fase 2 sin MVP estable salvo excepción documentada (riesgo alto).

---

## Matriz oferta vs. madurez

| Madurez | Oferta inicial |
|---------|----------------|
| 1 — Caótico | Auditoría + MVP registro |
| 2 — Manual | MVP registro + seguimiento |
| 3 — Herramientas sueltas | Captación/clasificación + reporting |
| 4 — Estable | Fase 2 + mantenimiento |

---

## Mensajes de venta por oferta (una línea)

- **Auditoría:** “Claridad sin compromiso de compra.”
- **MVP:** “Una automatización que podéis medir en 30–60 días.”
- **Seguimiento:** “Que ningún lead se quede olvidado en la hoja.”
- **Captación:** “Un solo sitio donde aterrizan todas las solicitudes.”
- **Reporting:** “Números simples cada lunes para decidir.”
- **Fase 2:** “Conectar lo que ya funciona, no empezar de cero.”
- **Mantenimiento:** “Que no se rompa cuando cambiéis el formulario.”

---

## Límites transversales (todas las ofertas)

- Sin datos clínicos ni promesa sanitaria.
- Sin “automatización total”.
- Sin WhatsApp/calendario/voz en paquetes que no lo indiquen explícitamente como fase 2.
- Sin precios en frío en LinkedIn; derivar a propuesta.
